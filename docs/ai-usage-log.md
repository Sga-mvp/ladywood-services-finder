# AI Usage Log

This document records every meaningful use of generative AI tools during the
project. It exists to support the AI-declaration slide in the final presentation
(5% of the module mark) and to maintain transparency about which parts of the
work involved AI assistance and which did not.

## How to add an entry

Each entry should record:

- **Date**
- **Tool** (e.g. Claude, GitHub Copilot, Microsoft Copilot)
- **What it was used for** — be specific
- **Why** — what the alternative would have been, and why AI was appropriate
- **What was kept** — verbatim, edited, or used only as a starting point

Add entries in reverse chronological order (newest at the top).

## 2026-06-03 — Claude (Anthropic)

**Used for:** Analysing the assignment brief and the EWB design challenge PDF,
shortlisting candidate problems, drafting the initial problem statement
(`docs/problem-statement.md`), and generating the initial repository scaffolding
(README, .gitignore, requirements.txt, Flask app skeleton, pytest configuration,
GitHub Actions CI workflow).

**Why:** Two efficiency goals. First, summarising and cross-referencing the
EWB brief's eight challenge areas to identify the strongest fit for a software
prototype was faster with AI assistance than reading and re-reading the PDF.
Second, repository scaffolding is well-trodden boilerplate — Flask app factory
pattern, pytest fixtures, GitHub Actions YAML — where AI generation saves time
without affecting the substantive engineering of the project. The conceptual
choices (Flask vs Django, GitHub Actions from day one, the specific test
strategy) were made by me after weighing the options Claude laid out.

**What was kept:** The problem statement was generated by Claude from a brief
I gave it (target users, scope, framing) and then edited by me before commit.
The repository scaffolding was used largely as-is, with the understanding that
none of it constitutes the substantive engineering of the solution — it is
project setup that any tutorial or template would produce similarly.

**Not used for:** Choosing the project direction (that was my decision after
reviewing the shortlist), writing the substantive design rationale, or
generating any user-facing content.
